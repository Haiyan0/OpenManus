# 多环境配置加载设计（dev/test 按启动参数选择）

- 日期：2026-08-14
- 状态：待用户审查
- 关联模块：app/config.py、6 个启动入口、config/ 目录

## 背景与问题

用户需要不同部署环境使用不同 config 配置。当前状态：

1. `config/config.toml` 已改名为 `config_dev.toml`（开发环境），新增 `config_test.toml`（测试环境）。
2. `app/config.py` 的 `_get_config_path()` 硬编码 `config/config.toml`（不存在则回退 `config.example.toml`）——改名后**永远加载不到 dev 配置**，会静默回退 example。
3. 启动方式期望：`python main.py dev` / `python main.py test`（位置参数）指定环境。

## 目标

- 通过启动参数（`python xxx dev|test`）或环境变量（`OPENMANUS_ENV=test`）选择配置文件 `config/config_{env}.toml`。
- 不传参数时默认 `dev`（开发机日常习惯，兼容现有不带参启动）。
- 参数与环境变量双通道，参数优先。
- 配置文件（含密钥）不入库。

## 已确认决策（用户）

1. **默认环境 = dev**：不传参时加载 `config_dev.toml`。
2. **参数 + 环境变量双通道**：入口位置参数优先；`OPENMANUS_ENV` 环境变量支持 uvicorn 直启 / IDE / Docker 等场景。
3. **配置文件不入库**：`config/.gitignore` 追加 `config_dev.toml`、`config_test.toml`。

## 方案（已选：环境变量桥接 + 入口延迟 import）

### 改动点 1：`app/config.py` 环境解析与文件选择

- 新增环境解析：三层优先级 `位置参数（经环境变量写入） > OPENMANUS_ENV 环境变量 > 默认 "dev"`。
  - 注意：config 层**不直接读 sys.argv**（避免配置层耦合 CLI），只认环境变量 `OPENMANUS_ENV`。
- `_get_config_path()` 改为按环境选择：`config/config_{env}.toml`。
- **合法环境集合 = config 目录下实际存在的 `config_*.toml` 文件**（动态枚举，未来新增 prod 环境无需改代码），环境名为 `_get_config_path` 传入参数 `env`。
- 错误处理：
  - 指定环境文件不存在（`config_{env}.toml` 缺失）→ 明确报错（`FileNotFoundError`，报错信息含可用文件清单），**不静默回退**——防止测试/生产环境悄悄用错配置。
  - `config.example.toml` 兜底逻辑保留：**仅当默认 dev 且 config_dev.toml 不存在时**回退 example（与现有行为一致）。

### 改动点 2：启动入口脚本（统一模式）

入口清单：`main.py`、`run_flow.py`、`run_mcp.py`、`run_mcp_server.py`、`sandbox_main.py`、`web_run.py`。

每个入口统一为（argparse 位置参数 `env`，`nargs="?"` 可空）：

```python
# 1) argparse 解析位置参数 env（可空）
# 2) 若传入 env：os.environ["OPENMANUS_ENV"] = env   ← 参数优先
# 3) 之后才 import app.* 模块（当前 import 在文件顶部，会先于
#    参数解析触发 app.config 单例加载，必须移到参数解析之后）
```

关键约束：`app/config.py` 模块级 `config = Config()` 在**首次 import 时**完成加载，所以环境变量必须在任何 `from app.config import ...` 之前写入。

- `web_run.py` 特殊点：`uvicorn.run("app.web.server:app")` 以字符串导入，主进程启动时加载模块——在 `uvicorn.run` 之前设置环境变量即可生效（`reload=False`，单进程）。

### 改动点 3：`config/.gitignore`

追加：

```
config_dev.toml
config_test.toml
```

密钥（API Key、MySQL 密码、JWT secret）不进仓库；`config.example.toml` 继续作为入库模板。

## 数据流

```
python main.py test
  → main.py 解析位置参数 env="test"
  → os.environ["OPENMANUS_ENV"] = "test"
  → import app.agent.manus（触发 app.config 首次加载）
  → Config._get_config_path() 读 OPENMANUS_ENV → config/config_test.toml
  → 加载并解析 → 单例 config 持有 test 环境配置

uvicorn app.web.server:app（部署场景）
  → 环境变量 OPENMANUS_ENV=test 预先设置
  → import 时同样按 config_test.toml 加载
```

## 错误处理与边界

- 环境指向不存在的文件（如 `python main.py prod` 但 config_prod.toml 未创建）→ `FileNotFoundError`，报错信息含 config 目录下可用环境清单，不静默回退。
- 默认 dev 缺失 → 回退 `config.example.toml`（现有行为保留，仅 dev 兜底）。
- 环境变量 `OPENMANUS_ENV=""`（空串）→ 视为未设置，走默认 dev。

## 测试计划

1. **环境解析与文件选择（`tests/test_config_env.py` 新建）**：
   - `OPENMANUS_ENV=test` → 选择 `config/config_test.toml`（用 monkeypatch 指到临时目录 + 假文件，避免依赖真实密钥文件）
   - 未设置环境变量 → 默认 `config_dev.toml`
   - 指定环境文件缺失 → `FileNotFoundError`（报错含可用环境清单）
   - dev 文件缺失 → 回退 example
   - 空字符串环境变量 → 视为 dev
2. **入口参数解析（轻量）**：验证入口脚本位置参数 → 环境变量的桥接逻辑（提取为可测函数或直接用 subprocess 冒烟）。
3. **现有回归**：`pytest tests/` 全量（重点 `tests/web/test_config.py`——web 段加载不受影响）。

## 范围外

- 不改 `config.example.toml` 等模板文件内容。
- 不引入新的配置格式/优先级系统（如多文件合并、分层覆盖）。
- 不改 `mcp.json` 的加载（与 toml 环境无关；如需按环境区分 MCP，留作后续）。
- 不处理 `.env` 文件加载（无 dotenv 依赖）。

## 风险

- 低：改动集中在 config 层文件选择逻辑 + 入口脚本 import 时机，无架构变化。
- 中：入口脚本 import 挪动若漏改某入口，该入口将永远用默认 dev——由测试与代码审查覆盖。
- 误把密钥文件入库：.gitignore 更新后，未跟踪文件不会被 `git add -A` 带入；已在 git 索引中的文件需 `git rm --cached` 处理（当前两文件均未跟踪，无此问题）。
