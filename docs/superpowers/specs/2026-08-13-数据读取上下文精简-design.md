# 数据读取上下文精简设计（预览 + 统计结果，全量数据不进上下文）

- 日期：2026-08-13
- 状态：待用户审查
- 关联 Agent：QuickQuery、DataAnalysis
- 关联工具：NormalPythonExecute、CompanyDataLookup

## 背景与问题

用户在 Web 聊天（QuickQuery/DataAnalysis）中做数据查询与统计时，每次任务的时间消耗和 token 消耗都很长。

根源分析（已确认代码现状）：

1. **`NormalPythonExecute.execute()`（app/tool/chart_visualization/python_execute.py:43）将脚本 stdout 全量注入 system 通道**（Bug1 修复设计：不截断，以 system message 形式注入下一轮 think，使模型能基于完整数据回答）。
2. 该注入**没有上限**：一旦模型在脚本里打印全量数据（如 `df.to_string()`、`print(df)`、遍历打印行），全量数据就进入上下文 → token 爆炸、推理变慢。
3. **提示词缺约束**：`NormalPythonExecute` 的 code 参数描述、QuickQuery/DataAnalysis 的 system prompt 都没有要求「读取数据只打印预览（列名 + 前 5 行）、统计脚本只输出统计结果」，模型无从知晓该规范。

## 目标

- 数据读取环节：脚本只输出数据预览（列名、形状、前 5 行），让模型"看一眼数据长什么样"。
- 统计环节：模型基于预览直接编写统计脚本，脚本只 print 统计结果（聚合、分组、结论数字）。
- 上下文只包含：预览 + 统计结果 + 结论。**全量原始数据永不进入上下文**。
- 效果：减少 token 消耗与每轮耗时。

## 方案（已选：提示词引导 + 硬性兜底截断）

### 改动点 1：`NormalPythonExecute` 工具描述加「数据读取规范」（软约束，主约束）

文件：`app/tool/chart_visualization/python_execute.py`，`parameters.properties.code.description` 的「## 注意事项」中新增：

```
## 数据读取规范
- 读取数据文件（CSV/Excel 等）时，只打印数据预览：列名（df.columns.tolist()）、
  数据形状（df.shape）、前 5 行（df.head(5)），确认数据结构即可
- 严禁打印全量数据（df.to_string()、print(df)、遍历打印所有行等）
- 统计分析脚本只 print 统计结果（聚合值、分组汇总、结论数字），不要 print 原始数据
```

注意保留原有 `{directory}` format 占位符兼容性（description 整体经 `.format(directory=...)` 渲染）。

### 改动点 2：`NormalPythonExecute.execute()` 加保护性截断（硬兜底）

文件：`app/tool/chart_visualization/python_execute.py`，`execute()` 中构造 `ToolResult(system=...)` 前：

- 新增常量 `MAX_SYSTEM_CHARS = 50000`（对齐 QuickQuery/DataAnalysis 的 `max_observe = 50000`）。
- stdout 长度 ≤ 阈值：维持现状（全量注入，Bug1 设计不变）。
- stdout 长度 > 阈值：**保留头部 20,000 字符 + 尾部 30,000 字符**，中间以省略标记替换，并附加说明：

  ```
  ...[stdout 共 N 字符超过上限已截断，仅保留头部预览与尾部统计结果]...
  ```

  理由：头部通常含数据预览（列名/head），尾部通常含统计结果（模型习惯最后 print 结论），两头都保留可避免模型因丢结果被迫重跑脚本。

- 截断后 output 摘要中的字符数同步更新（`stdout 已载入 system（N 字符）` 中的 N 改为截断后的实际长度）。

### 改动点 3：QuickQuery system prompt 加「数据读取与输出规范」

文件：`app/prompt/quick_query.py`，`SYSTEM_PROMPT` 的「## 约束」中新增：

```
- **数据读取只输出预览**：python_execute 读取 CSV 时只打印列名、数据形状和前 5 行，
  严禁打印全量数据（df.to_string()/print(df)）
- **只把统计结果带进上下文**：统计脚本只 print 聚合值、分组汇总、结论数字，
  基于这些统计结果直接回答用户，不要让全量原始数据进入上下文
```

### 改动点 4：DataAnalysis system prompt 加同样规范

文件：`app/prompt/visualization.py`，`SYSTEM_PROMPT` 的「# 数据与环境」第 3 条之后新增小节：

```
# 数据读取与输出规范
- python_execute 读取数据文件时只打印数据预览（列名、形状、前 5 行）
- 严禁打印全量数据（df.to_string()/print(df)），全量数据不进上下文
- 统计脚本只 print 统计结果与关键结论，图表与报告基于统计结果生成
```

### 改动点 5（可选微调）：`CompanyDataLookup.query` 输出引导语

文件：`app/tool/company_data_lookup.py`，`_execute_query` 返回的提示语（company_data_lookup.py:527）追加一句：

```
读取该 CSV 时只打印预览（列名与前 5 行），请勿打印全量数据。
```

说明：`_execute_query` 已返回「行数 + 列名 + 前 5 行预览 + CSV 路径」，本身符合"预览"精神，此改动仅引导模型后续 `read_csv` 时保持同样习惯。local 模式（`_execute_local`）只返回文件列表，无数据，无需改动。

## 数据流（改动后）

```
用户提问 → CompanyDataLookup.list_tables（数据字典走 system）→ 反驳自省
  → query（写 CSV + 返回行数/列名/前5行预览 + 路径）
  → python_execute #1：pd.read_csv → 打印 df.shape / df.columns / df.head(5)  ← 仅预览
  → python_execute #2：统计脚本 → print 聚合值/分组汇总/结论                ← 仅统计结果
  → 模型基于统计结果直接回答 → Terminate
```

任何一步若模型打印了全量数据 → 改动点 2 的 50000 字符兜底截断拦截，上下文仍受控。

## 错误处理与边界

- 截断仅影响 system 注入内容；不截断工具原始返回值（`super().execute` 结果不修改），不影响其他消费方。
- 阈值与保留比例若后续发现统计输出本身超长（如大分组表），可调 `MAX_SYSTEM_CHARS` 与头尾比例，无需改结构。
- 截断标记为英文 `...[ ... ]...` 避免中文转义问题（与现有代码风格一致）。

## 测试计划

1. **单元测试（新增 `tests/tool/test_python_execute_preview.py` 或扩展现有）**：
   - stdout ≤ 阈值 → system 全量注入，无截断标记
   - stdout > 阈值 → system 注入含头部与尾部内容 + 截断标记，长度不超过阈值
   - 截断后 output 摘要字符数与实际注入长度一致
   - 通过 mock 基类 `PythonExecute.execute` 返回构造的超长 observation，避免真实执行
2. **提示词回归**：断言 `NormalPythonExecute.parameters` 描述与两个 system prompt 包含「前 5 行」等关键约束词（防未来被误删）。
3. **集成验证（手动）**：Web 聊天 QuickQuery 会话跑一次真实查询，检查：查询返回预览、脚本输出仅为预览+统计结果、对话上下文无全量数据、响应时间/token 改善。
4. **现有回归**：`pytest tests/` 全量通过（重点 `tests/tool/`、`tests/web/`）。

## 范围外

- 不改 `max_observe`（50000）数值。
- 不新增"预览专用工具"（避免增加模型决策负担；当前链路已足够）。
- 不改 CLI（main.py）路径 —— 但 NormalPythonExecute 改动对 CLI 同样生效，属于行为增强而非破坏。

## 风险

- 低：改动集中在工具描述文本、system prompt 文本与一处截断逻辑，无架构变化。
- 兜底截断可能截掉个别超长统计输出 → 模型可依据截断标记重跑精简脚本，一次额外调用成本可接受。
