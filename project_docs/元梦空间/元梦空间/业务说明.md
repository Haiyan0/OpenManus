## 1. 项目概述

元梦空间是平台核心元宇宙 App，业务围绕虚拟资产、社交关系与交易展开：

- 用户体系（tan_user，21 万+ 用户）与两级层级分销关系（tan_class_user）
- 资产订单中心（tan_common_order + tan_common_order_goods）：order_type 覆盖元豆充值、地块、建筑、内装、会员、数字人、电影、会议室等 30+ 品类，金额以平台虚拟货币「元豆」为主
- 部落商城订单（tan_tribe_order）：含发货、售后、分账结算完整链路
- 地块竞价交易（tan_area_bid_order）：买卖双方撮合成交

数据为 MySQL 业务库实时数据，各业务表均带软删除字段 deleted_at。

## 2. 涉及数据表

| 表名 | 用途 | 备注 |
|------|------|------|
| tan_user | 用户注册信息表 | 核心用户表；主键 user_id（另有原始自增 real_user_id，见口径）；时间字段 created_at |
| tan_common_order | 用户资产订单表 | 订单主表，主键 order_id；时间字段 created_at |
| tan_common_order_goods | 用户购买商品订单表 | 订单商品明细，主键 order_goods_id；经 order_no 关联主表 |
| tan_class_user | App 用户层级关系表 | 两级层级（上级/上两级）；主键 id；时间字段 created_at |
| tan_tribe_order | 用户部落订单购买记录表 | 部落/公会商城订单；主键 order_id；时间字段 created_at |
| tan_area_bid_order | 用户购买地块订单 | 地块竞价成交订单；主键 order_id；时间字段 created_at |

## 3. 字段口径说明

### tan_user（用户表）

- **user_id / real_user_id 双 ID 并存**：user_id 为业务用户 ID，**已验证各订单/关系表的 user_id 均指向 tan_user.user_id（覆盖度 99.8%+）**；real_user_id 为用户原始自增 ID，业务表不引用它。跨表 JOIN 统一用 user_id
- status：**统计有效用户用 status=1**（枚举见表注释）
- vip_level：等级枚举见表注释；vip_expiry_time 为 vip 过期时间（bigint Unix 时间戳）
- consume_level：消费等级区间（0-5=消费0元，6-10=消费80-200元，11-20=消费260-800元…），注释在 20 档后省略，20 档后不看
- gold：碳金币（decimal(22,4)）
- reigster_platform：注册平台枚举见表注释
- fst_num / snd_num：一级/二级下线人数（与 tan_class_user 层级关系对应）
- cert_name / cert_no / cert_image：实名认证三件套，**敏感字段，输出时勿明文展示**

### tan_common_order（资产订单主表）

- **order_price（订单金额）与 pay_price（实际支付金额，优惠后）**：统计成交额用 pay_price + pay_status=2（已付款），单位元豆
- 状态字段分散：pay_status（付款）/ order_status（订单）/ cancel_status（取消）并存，枚举见表注释，**口径勿混用**；该表无退款状态字段，退款口径待确认
- order_type：订单类型 30+ 值，完整枚举见表注释；其中 **160=租房、1010=租用原住房 与「元租房」项目业务相关**，跨项目统计注意口径
- **offset_the_price 是唯一人民币元字段**（抵扣金额），其余金额均为元豆；offset_currency 抵扣货币类型枚举见表注释
- is_payer / payer_order_no：是否帮付与帮付单号（枚举见表注释）
- association_id（部落 id）/ organization_id（组织 id）：对应主数据表不在本库

### tan_common_order_goods（订单商品明细）

- 与主表经 **order_no** 关联（一张订单多条明细，1:N；已验证 100% 命中主表）
- goods_id 为 varchar(50) 字符串商品 ID；goods_name / cover_url / goods_spec 为商品冗余展示字段
- 校验口径：各明细 pay_price 之和应对应主表 pay_price

### tan_class_user（用户层级）

- user_id / superior_fst（上一级）/ superior_snd（上两级）均指向 tan_user.user_id（已验证 100%）
- deleted_fst_friend_at / deleted_sub_friend_at 非空 = 上下级关系已解除，**统计有效层级必须排除**

### tan_tribe_order（部落商城订单）

- type：订单类型枚举见表注释（GS 公会/公会/个人商家）；**owner_id 按 type 表示不同含义**
- 金额口径勿混用：order_price（订单金额）/ pay_price（实际付款）/ gold（实际支付元豆）/ pay_third_coupon（三方券）/ pay_silver_bean（银豆）
- 分账结算：**统计已结算用 is_settled=2**；divide_status / settled_time / settled_amount / settled_ratio 见表注释
- 售后与物流：refund_status / is_cancel_refund / is_invoice / delivery_* / receipt_* 枚举见表注释
- order_source / create_source：订单来源（商城/gs、mr 商城/直播带货），枚举见表注释

### tan_area_bid_order（地块竞价成交）

- **两阶段口径：先看 state（支付阶段，枚举见表注释），再看 status（付款完成，枚举见表注释）；统计成交用 state=0 AND status=3**
- buyer_user_id / seller_user_id → tan_user.user_id（已验证 100%）；pledge_id 押金 id、record_id 出价记录 id
- 分账：platform_fee_amount（分账手续费）/ seller_amount（卖家分账）/ space_acquisition_fee（平台分账手续费比例，**比例基数待确认**）
- settled_time：订单结算时间

## 4. 表关联关系

- 订单 → 明细：tan_common_order.order_no = tan_common_order_goods.order_no（1:N，已验证 100% 命中）
- 层级 → 用户：tan_class_user.user_id / superior_fst / superior_snd 均指向 tan_user.user_id（已验证）
- 部落订单 → 用户：tan_tribe_order.user_id → tan_user.user_id（已验证 100%）
- 资产订单 → 用户：tan_common_order.user_id → tan_user.user_id（已验证 99.9%）
- 地块订单 → 用户：tan_area_bid_order.buyer_user_id / seller_user_id → tan_user.user_id（已验证 100%）
- 关联坑：
  - JOIN 用户表统一用 tan_user.user_id，勿用 real_user_id（业务表不引用它，已验证 0% 命中）
  - 所有业务表带 deleted_at 软删除，统计时补 WHERE deleted_at IS NULL
  - tan_common_order 的 association_id / organization_id 指向部落/组织，对应主数据表不在本库

## 5. 常用查询 SQL 示例

-- 每日资产订单实际支付金额（元豆）趋势
SELECT DATE(created_at) AS day,
       SUM(pay_price) AS paid_yuandou
FROM tan_common_order
WHERE pay_status = 2 AND deleted_at IS NULL
GROUP BY DATE(created_at)
ORDER BY day;

-- 按订单类型统计支付金额 TOP 类型
SELECT order_type,
       COUNT(*) AS order_cnt,
       SUM(pay_price) AS paid_yuandou
FROM tan_common_order
WHERE pay_status = 2 AND deleted_at IS NULL
GROUP BY order_type
ORDER BY paid_yuandou DESC;

-- 部落商城订单分账结算情况（已结算口径）
SELECT DATE(settled_time) AS day,
       COUNT(*) AS settled_cnt,
       SUM(settled_amount) AS settled_total
FROM tan_tribe_order
WHERE is_settled = 2 AND deleted_at IS NULL
GROUP BY DATE(settled_time)
ORDER BY day;

-- 地块成交金额（支付健康且交易完成）
SELECT DATE(settled_time) AS day,
       COUNT(*) AS deal_cnt,
       SUM(price) AS deal_total,
       SUM(platform_fee_amount) AS fee_total
FROM tan_area_bid_order
WHERE state = 0 AND status = 3 AND deleted_at IS NULL
GROUP BY DATE(settled_time)
ORDER BY day;

-- 用户层级关系明细（有效关系）
SELECT u.user_id,
       u.nickname,
       c.depth,
       c.superior_fst,
       c.superior_snd,
       c.bind_time
FROM tan_class_user c
JOIN tan_user u ON u.user_id = c.user_id
WHERE c.deleted_at IS NULL
  AND c.deleted_fst_friend_at IS NULL
  AND c.deleted_sub_friend_at IS NULL
LIMIT 100;

## 6. 注意事项

- 数据更新频率：待确认（疑似准实时）
- **软删除惯例**：所有 tan_* 业务表均带 deleted_at，统计查询务必过滤 deleted_at IS NULL
- **金额单位**：订单金额以「元豆」为主（pay_price、gold、pay_silver_bean 等）；只有 offset_the_price 是人民币元。**元豆兑人民币汇率 10:1（10 元豆 = 1 元人民币）**，人民币对账时除以 10
- **大表查询**：tan_user（21 万）、tan_class_user（21 万）、tan_common_order（34 万）、tan_common_order_goods（35 万）——聚合查询务必加时间范围与状态过滤
- **敏感字段**：tan_user.cert_no（身份证号）、cert_image、mobile、password、salt 等输出时须脱敏
- 枚举值以 list_tables 返回的表注释为准；若表注释与本文档口径冲突，先 ask_human 确认再查询
