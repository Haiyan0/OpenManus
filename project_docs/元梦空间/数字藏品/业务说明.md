## 1. 项目概述

元梦空间数字藏品业务由两套体系构成：

- **藏品商城（fa_ 前缀）**：独立商城体系，含商城用户（fa_user）、藏品订单（fa_orders，含盲盒）、订阅会员卡订单（fa_card_orders）
- **平台侧藏品资产（tan_ 前缀）**：用户持有的数字藏品记录（tan_user_has_nfr，150 万行）与碎片/碎金流水（tan_space_piece_log，207 万行）

核心玩法链路（推断，待确认）：商城购买/获赠藏品 → 形成持有记录（source=一级市场购买/获赠）→ 布展释放碎片 → 碎片流水入账；碎片可合成数字藏品。持有藏品按日释放碎片（daily_release_amount × release_days）。

## 2. 涉及数据表

| 表名 | 用途 | 备注 |
|------|------|------|
| fa_user | 用户注册信息表（藏品商城用户） | 主键 id；时间字段 createtime（Unix 秒时间戳） |
| fa_orders | 藏品订单表 | 主键 id；时间字段 create_time（datetime） |
| fa_card_orders | 订阅会员卡订单表 | 主键 id；时间字段 create_time |
| tan_user_has_nfr | 用户通过活跃行为合成的数字藏品记录表 | 主键 id；时间字段 created_at；大表 150 万行 |
| tan_space_piece_log | 藏品碎片获得记录表 | 主键 id；时间字段 created_at；大表 207 万行 |

## 3. 字段口径说明

### fa_user（商城用户表）

- 主键 id（int unsigned，商城体系用户 ID，已验证 fa_orders / fa_card_orders 的 user_id 100% 指向它）
- status：**统计有效用户用 status='normal'**（枚举见表注释）
- **时间字段口径特殊**：jointime / createtime / logintime / prevtime / loginfailuretime 为 bigint **Unix 秒时间戳**（已验证值域 1.77e9），与 fa_orders 的 datetime 口径不同，对比时用 FROM_UNIXTIME 转换
- money：余额（元，decimal(10,2)）；score：积分
- is_real：实名认证标记（枚举见表注释）

### fa_orders（藏品订单表）

- **amount：订单金额=实际支付金额（元，decimal(10,2)）；统计销售额用 amount + pay_state='PAID'**
- state（订单状态）/ pay_state（支付状态）枚举见表注释；**成交口径用 pay_state='PAID'**
- coupon：三方积分抵扣金额（int 类型）
- num：藏品数量；goods_id：商品 ID
- is_open：是否已开盲盒（0/1）；err_num / err_reason：错误次数 / 异常原因（多次处理后）
- fee_amount：手续费金额（**varchar(20) 字符串类型**，数值运算需先 CAST）
- transaction_id / out_trans_id：支付交易号 / 外部订单号

### fa_card_orders（订阅会员卡订单表）

- 结构与 fa_orders 同源（19 字段），无 goods_id / is_open / err_* 字段
- card_id：卡 ID；group_id：组 ID
- amount / state / pay_state 口径同 fa_orders

### tan_user_has_nfr（数字藏品持有记录表）

- user_id：**指向 tan_user.user_id（平台用户，已验证 99.9%），不是 fa_user.id**
- nfr_id（NFR 类型 ID）/ nfr_chain_id（链表 ID）/ compound_id（合成 ID，碎片合成来源）
- status / source / sell_type / lock_type / unlock_source 枚举见表注释（状态机：可用 → 布展 → 锁定 → 已兑换/已出售/已重铸）
- 释放机制：daily_release_amount（每日释放量）× total_release_days（赠送天数）；release_days 已释放天数；hold_time 保持期到期；release_time 布展释放碎片时间
- tx_hash：**binary(34) 类型**，查询展示需 HEX() 转换
- issuer_type（发行商 1=元梦平台 2=三方）/ source_platform_id（0=一级平台）枚举见表注释

### tan_space_piece_log（碎片流水表）

- user_id / from_user_id → tan_user.user_id（已验证 100%）
- **type：1=增项 2=减项；净增 = 增项 − 减项**
- space_piece：碎片值（decimal(20,4)）；before / after：变更前后值（对账用）
- source：碎片来源 10 种（布展/层级分成/合成/赠送/退回/补偿等，完整枚举见表注释）
- broken_gold_brick：碎金（decimal(20,4)，平台积分单位）
- out_id / record_id：外部 id / 记录编号

## 4. 表关联关系

- 藏品订单 → 商城用户：fa_orders.user_id = fa_user.id（已验证 100%）
- 会员卡订单 → 商城用户：fa_card_orders.user_id = fa_user.id（已验证 100%）
- 持有记录 → 平台用户：tan_user_has_nfr.user_id → tan_user.user_id（已验证 99.9%）
- 碎片流水 → 平台用户：tan_space_piece_log.user_id → tan_user.user_id（已验证 100%）
- **两套用户体系并存（重要）**：fa_user（商城用户，5 千）与 tan_user（平台用户，21 万）之间**无直接外键线索**，映射关系待业务侧确认（可能经 mobile / 微信 openid 关联）。藏品商城订单与平台持有记录分属两套体系，跨体系统计需先解决用户映射
- 业务链路（推断，待确认）：fa_orders 购买 → tan_user_has_nfr 持有（source=一级市场购买）→ 布展/释放 → tan_space_piece_log 入账（source=布展）
- 关联坑：
  - 持有/碎片表的 user_id 是平台用户（tan_user.user_id），**不是** fa_user.id（已验证 0% 命中）
  - 两张大表（150 万/207 万行）JOIN 前务必先按时间、用户范围过滤

## 5. 常用查询 SQL 示例

-- 藏品销售额按月（商城侧）
SELECT DATE_FORMAT(create_time, '%Y-%m') AS month,
       SUM(amount) AS sales_yuan
FROM fa_orders
WHERE pay_state = 'PAID'
GROUP BY DATE_FORMAT(create_time, '%Y-%m')
ORDER BY month;

-- 盲盒开启率
SELECT COUNT(*) AS total_orders,
       SUM(CASE WHEN is_open = 1 THEN 1 ELSE 0 END) AS opened_orders
FROM fa_orders
WHERE pay_state = 'PAID';

-- 藏品持有状态分布（限定时间范围）
SELECT status, COUNT(*) AS cnt
FROM tan_user_has_nfr
WHERE deleted_at IS NULL
  AND created_at >= '2026-01-01'
GROUP BY status;

-- 用户碎片净增排行（增项-减项）
SELECT user_id,
       SUM(CASE WHEN type = 1 THEN space_piece ELSE -space_piece END) AS net_piece
FROM tan_space_piece_log
WHERE deleted_at IS NULL
  AND created_at >= '2026-01-01'
GROUP BY user_id
ORDER BY net_piece DESC
LIMIT 20;

-- 订阅会员卡收入按月
SELECT DATE_FORMAT(create_time, '%Y-%m') AS month,
       SUM(amount) AS card_revenue
FROM fa_card_orders
WHERE pay_state = 'PAID'
GROUP BY DATE_FORMAT(create_time, '%Y-%m')
ORDER BY month;

## 6. 注意事项

- 数据更新频率：待确认（疑似准实时）
- **大表严格限范围**：tan_space_piece_log（207 万行）、tan_user_has_nfr（150 万行），查询必须加时间/用户/状态过滤，禁止全表扫描
- **两套用户体系**：fa_*（商城）与 tan_*（平台）用户映射关系待确认，跨体系统计前先向业务侧确认
- **时间字段口径不一**：fa_user 的时间字段是 Unix 秒时间戳（bigint），fa_orders / fa_card_orders 是 datetime；对比时用 FROM_UNIXTIME(createtime) 对齐
- **类型陷阱**：fa_orders.fee_amount 是 varchar，数值运算需 CAST；tan_user_has_nfr.tx_hash 是 binary(34)，展示需 HEX()
- 金额单位：fa_* 表金额为人民币元；碎片（space_piece）/ 碎金（broken_gold_brick）为平台积分单位，不可与金额混算
- 软删除惯例：tan_* 表均带 deleted_at，统计时过滤 deleted_at IS NULL；fa_* 表无软删除字段
